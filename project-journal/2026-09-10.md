# Project Work Log — 2026-09-10

Today, I completed the first stage of the project, moving from overall system design toward practical development preparation. I first developed the architecture for the STM32 real-time streaming system and subjected it to multiple rounds of adversarial review, deliberately looking for potential weaknesses in resource constraints, real-time behavior, DMA and buffer ownership, RTOS task organization, runtime measurement, experimental protocol, fault handling, and the validation process. This resulted in Architecture v3.2.2 being selected as the implementation baseline. On the hardware side, I carried out a similarly strict engineering feasibility review of the candidate development board and selected the NUCLEO-F446RE. Rather than relying only on headline specifications, I checked the STM32F446RE’s CPU performance, SRAM, Flash, ADC, DMA, timers, serial communication resources, and expected worst-case workloads against the requirements of the planned experiments, and confirmed that the board provides an adequate resource basis for the project within the approved design scope. I then began setting up the development environment on Windows 11 with an emphasis on isolation, reproducibility, and avoiding unnecessary complexity. I created the local project repository and its public GitHub repository, configured Git identity and repository policies, created a dedicated Python 3.12.13 virtual environment with uv and a dependency lock file, and installed and verified CMake 3.31.12, Ninja 1.13.1, Arm GNU Toolchain 14.2.Rel1, and STM32CubeMX 6.18.1. During setup, I also encountered and resolved an interrupted ARM toolchain download and an incorrect extraction location, using SHA-256 verification, file comparisons, and directory cleanup to ensure that the final toolchain installation was intact and trustworthy. I then performed a CMake + Ninja + ARM GCC cross-compilation smoke test, successfully generating a Cortex-M4F object file with the expected v7E-M, VFPv4-D16, and hard-float attributes. Finally, I installed and verified STM32CubeF4 V1.28.3 and recorded the detailed environment bring-up process, tool versions, paths, incidents, and evidence boundaries in the repository. At this point, the project has a reproducible and traceable development foundation for the next stages: creating the NUCLEO-F446RE firmware project, compiling and linking the target firmware, flashing and debugging the real board, and progressively executing the planned R0–R7 validation gates.
