# Firmware Build Baseline

## Scope

This document records the reproducible computer-side firmware build procedure for the minimal STM32CubeMX-generated `NUCLEO-F446RE / STM32F446RE` project.

This procedure proves host-side configure, compile, link, and artifact packaging only. It does **not** prove flashing, target boot, ST-LINK connectivity, VCP communication, peripheral behavior, or any board-level validation gate.

## Inputs

Repository source tree:

```text
firmware/cubemx/
```

CubeMX baseline:

```text
STM32CubeMX 6.18.1
STM32CubeF4 V1.28.3
CMake + GCC
```

Required host tools are documented in `docs/environment.md`.

## Clean build procedure

Run from the repository root in Windows PowerShell.

Replace `<tools-root>` with the local tools directory.

```powershell
$repo      = (Get-Location).Path
$fw        = Join-Path $repo 'firmware\cubemx'
$build     = Join-Path $repo 'build\p0-a2'
$tools     = '<tools-root>'
$cmake     = Join-Path $tools 'cmake-3.31.12-windows-x86_64\bin\cmake.exe'
$ninja     = Join-Path $tools 'ninja-1.13.1-windows-x86_64\ninja.exe'
$armBin    = Join-Path $tools 'arm-gnu-toolchain-14.2.rel1-mingw-w64-x86_64-arm-none-eabi\bin'
$toolchain = Join-Path $fw 'cmake\gcc-arm-none-eabi.cmake'

$oldPath = $env:PATH

try {
    $env:PATH = "$armBin;$(Split-Path $ninja -Parent);$oldPath"

    if (Test-Path -LiteralPath $build) {
        Remove-Item -LiteralPath $build -Recurse -Force -ErrorAction Stop
    }

    & $cmake `
        -S $fw `
        -B $build `
        -G Ninja `
        "-DCMAKE_MAKE_PROGRAM=$ninja" `
        "-DCMAKE_TOOLCHAIN_FILE=$toolchain" `
        -DCMAKE_BUILD_TYPE=Debug

    if ($LASTEXITCODE -ne 0) {
        throw 'CMake configure failed.'
    }

    & $cmake --build $build --verbose

    if ($LASTEXITCODE -ne 0) {
        throw 'Firmware build failed.'
    }

    $elf = Join-Path $build 'cubemx.elf'
    $hex = Join-Path $build 'cubemx.hex'
    $bin = Join-Path $build 'cubemx.bin'

    & "$armBin\arm-none-eabi-objcopy.exe" -O ihex $elf $hex
    if ($LASTEXITCODE -ne 0) {
        throw 'ELF to HEX conversion failed.'
    }

    & "$armBin\arm-none-eabi-objcopy.exe" -O binary $elf $bin
    if ($LASTEXITCODE -ne 0) {
        throw 'ELF to BIN conversion failed.'
    }
}
finally {
    $env:PATH = $oldPath
}
```

The linker map is generated by the CubeMX CMake toolchain configuration as:

```text
build/p0-a2/cubemx.map
```

All files under `build/` are ignored by Git.


Verified ELF / ARM attributes:

```text
Machine: ARM
Version5 EABI
hard-float ABI
Tag_CPU_arch: v7E-M
Tag_CPU_arch_profile: Microcontroller
Tag_FP_arch: VFPv4-D16
Tag_ABI_VFP_args: VFP registers
```

The actual compile database contained:

```text
-mcpu=cortex-m4
-mfpu=fpv4-sp-d16
-mfloat-abi=hard
```

The build therefore uses the expected Cortex-M4F / ARMv7E-M / FPv4-SP-D16 / hard-float configuration.

## Evidence boundary

P0-A2 establishes only that the minimal generated STM32 project can be configured, compiled, linked, and packaged into target artifacts on the host computer.

The following remain untested until the physical board and data cable are available:

- ST-LINK connection
- flashing
- target boot
- on-board GDB debugging
- VCP/UART
- physical clock behavior
- ADC / TIM / DMA / DBM
- FreeRTOS runtime behavior
- any board-level timing result
- any R0-R7 hardware validation gate
